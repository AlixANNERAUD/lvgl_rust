# External LVGL Font Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compile generated font assets independently while exporting a stable, complete LVGL native configuration and preserving the legacy font workflow.

**Architecture:** The `lvgl_rust_sys` Cargo package declares `links` metadata and exports the exact native compile configuration to dependent build scripts. An example font package consumes that interface and owns a separate archive; an automated Cargo fixture mutates only a font input and verifies LVGL compilation and bindgen are not rerun.

**Tech Stack:** Rust 2021, Cargo build scripts and `links` metadata, `cc`, bindgen, C generated by `lv_font_conv`, Cargo integration tests.

**Spec:** `docs/superpowers/specs/2026-10-20-external-font-build-design.md`

## Global Constraints

- Font assets remain compile-time const data in firmware Flash/ROM; no runtime loading, copying, or rasterization.
- Font changes must not rerun LVGL C compilation or bindgen in external-font mode.
- Export actual include paths, defines, target-specific settings, and ABI-affecting compiler options; do not reconstruct LVGL configuration downstream.
- Preserve `LVGL_FONTS_DIR` as an explicit legacy mode; remove implicit working-directory `fonts/` discovery.
- Give font profiles deterministic unique symbols and support multiple linked variants.
- Treat temporary LVGL rendering buffers as distinct from persistent font asset storage.
- Validate ESP32-S3 when the toolchain is available and report unavailability explicitly.

## Review Focus

- Missing or malformed build metadata must fail clearly instead of silently compiling with a guessed ABI — test dependency metadata propagation and required key validation.
- Feature/environment combinations can produce differing LVGL ABI settings — test color-depth and custom `LVGL_CFLAGS` metadata.
- Font asset edits may inadvertently retrigger the parent build via directory watches — the incremental Cargo regression test must prove LVGL build-script and bindgen steps stay cached.
- Two profile objects may collide at link time — link distinct profile-qualified font symbols together.
- Generated constant objects can land in writable sections or be copied — inspect object/ELF section flags and document what could not be tested on embedded hardware.

### Task 1: Export the stable LVGL native build interface

**Files:**
- Modify: `Cargo.toml` (`[package]` `links` declaration)
- Modify: `build.rs` (centralize compile configuration and export metadata)
- Test: `tests/native_build_interface.rs` or a dedicated build-script fixture

**Interfaces:**
- Produces Cargo package `links = "lvgl_rust_sys"` and documented metadata variables `DEP_LVGL_RUST_SYS_INCLUDE_PATHS`, `DEP_LVGL_RUST_SYS_DEFINES`, `DEP_LVGL_RUST_SYS_CFLAGS`, and `DEP_LVGL_RUST_SYS_TARGET` (final names follow Cargo's links normalization and are verified by fixture).
- Export values must derive from the same normalized configuration applied to `cc::Build`, including LVGL/vendor/config/shim and enabled optional include paths, `LV_CONF_INCLUDE_SIMPLE`, selected color depth, `LVGL_CFLAGS`, and target compiler arguments where they affect ABI.
- Do not export host-only bindgen invocation details as target C compiler flags; distinguish common C defines/options from bindgen-specific arguments.

- [ ] **Step 1: Add a downstream fixture that prints all `DEP_*` values and asserts paths, defines, flags, and target are present.** Create a minimal dependent package with an executable `build.rs`; drive it using a local path dependency and a valid `DEP_LV_CONFIG_PATH` configuration.
- [ ] **Step 2: Run the fixture before implementation and confirm it fails because the `links` metadata is absent.** Run `cargo test --test native_build_interface -- --nocapture`; expect the fixture's metadata assertion to fail.
- [ ] **Step 3: Add `links = "lvgl_rust_sys"` and refactor `build.rs` to build one normalized configuration value used for `cc::Build` and Cargo `cargo:include`/`cargo:metadata` exports.** Keep every define and include applied to LVGL represented exactly once in this value.
- [ ] **Step 4: Assert exported values match the active configuration.** Include checks with `use-vendored-config`, a selected `color_depth_*` feature, and an ABI-affecting `LVGL_CFLAGS` entry; run the fixture and the library build.
- [ ] **Step 5: Commit the interface and tests.** `git add Cargo.toml build.rs tests && git commit -m "feat: export LVGL native build configuration"`.

### Task 2: Separate external font mode and retain the legacy mode

**Interfaces:**

- [ ] **Step 1: Add build-mode tests for default isolation and explicit legacy mode.** In temporary fixture crates, assert default mode emits no font path rerun directives and legacy mode compiles its C source and passes its header to bindgen.

- [ ] **Step 3: Make font integration conditional only on explicit `LVGL_FONTS_DIR`; remove `PWD/fonts` discovery and ensure only legacy mode adds font sources, headers, and watches.** Keep all LVGL sources and configuration watches intact.
- [ ] **Step 4: Document legacy coupling and the external-font recommendation; test default and legacy fixtures.** Run `cargo test --test font_build_modes` and `cargo test --lib`.
- [ ] **Step 5: Commit the mode behavior.** `git add build.rs README.md tests && git commit -m "build: isolate external fonts from LVGL compilation"`.
